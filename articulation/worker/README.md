# Articulation Autonomous Worker

This worker is designed to run on Jetson #1 and Jetson #2 using the same repository.

It does not replace the existing Qwen3.8 runtime. It connects to an OpenAI-compatible local endpoint configured by `LLM_BASE_URL`.

## Responsibilities

- Maintain a persistent research queue.
- Ask the local LLM to plan research queries.
- Search the web using a configured search provider.
- Fetch and extract public pages.
- Include community sources such as Reddit, GitHub and public discussions when returned by search.
- Ask the local LLM to synthesize evidence into Markdown.
- Store source metadata and run state in SQLite.
- Write results only under `articulation/docs/research/` by default.
- Never push automatically.
- Never operate on `main`.

## Quick start

Copy `config/worker.env.example` to your runtime environment and set:

- `LLM_BASE_URL`
- `LLM_MODEL`
- `SEARCH_PROVIDER`
- provider API key

Then:

```bash
cd articulation/worker
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m agent.run --job ai-stack-research
```

The worker is intentionally conservative. It creates commits locally only when `AUTO_COMMIT=true`. Push remains a human action.

## Jetson synchronization

Both Jetsons pull the same `articulation-mvp` branch. Each machine has a local role configured by environment:

- `JETSON_ROLE=research`
- `JETSON_ROLE=benchmark`
- `JETSON_ROLE=builder`

The worker itself is stateless across machines except for the SQLite state database. Git is the shared source of truth for research artifacts.

## Safety

The worker does not execute arbitrary shell commands generated by the model. The model can request structured research actions only. File writes are restricted to the Articulation research directory.
